# Native 日志与异常开发规范

> 适用：所有人工与 AI 编写的生产代码、后台线程、协议适配器和 GUI 回调。
> 本文细化 `AI工程规范.md`，不降低其安全要求。旧设计中的 `op{id}`、`child()` 和普通字符串结束行不再是实现合同；实际调用链复用固定版本的 `lumakit-observability`。

## 1. 先确定责任，再选择级别

日志用于回答“哪个操作，经过哪层，结果是什么，失败在哪里”，不是输出程序执行过程的流水账。新增日志前必须明确消费者、事件、所有者和字段。不要因为一次排查困难就把所有细节提高到 INFO/ERROR。

| 级别 | 必须使用的场景 | 不应使用的场景 |
| --- | --- | --- |
| INFO | 顶层操作入口、关键生命周期、完成结果；应用/引擎/会话开始与结束 | 每帧协议、每条消息、每个模型、循环进度、重复状态 |
| DEBUG | 下层服务/存储/外部调用的入口与成功出口；协议类型、字节数、分支原因、已被上层处理的诊断；幂等清理中已明确不影响结果的失败 | 密钥、原始参数、正文、SQL、用户绝对路径；DEBUG 不是安全例外 |
| WARN | 超时、降级、非正常结束、已恢复异常、清理失败；子操作失败终态 | panic、数据完整性损坏；普通成功或正常取消 |
| ERROR | 顶层操作最终失败，启动不能继续、数据完整性风险、程序不变量错误、Rust panic | 每层重复记录同一个错误；验证输入的每个字段；已正常取消 |
| TRACE | 本项目不使用正文级协议跟踪 | 任何凭据、请求/响应全文 |

固定生命周期合同：root ENTRY/EXIT/CANCEL 为 INFO，root ERROR 为 ERROR；子操作 ENTRY/EXIT/CANCEL 为 DEBUG、ERROR 为 WARN；TIMEOUT/UNFINISHED 为 WARN。这里的 ERROR 表示“这个顶层操作失败”，不等同“整个程序崩溃”；可恢复 HTTP 失败也必须有失败事实。不得通过改成成功或吞错来降低日志级别。

一个异常应有一个最终责任边界。允许“子操作 WARN + root ERROR”说明层级，不允许“service ERROR + UI ERROR + notice ERROR”重复报警。UI 展示失败不再重复记录已经由 root 记录的错误。

## 2. 调用链与终态

- 用户动作/独立后台任务/review 建立 root：`TraceContext::root(operation, layer) -> (TraceContext, OperationGuard)`。TraceId 为 32 位小写十六进制，创建不返回 Result。已有 Agent 的会话 root 在注册后以 REGISTERED 结束，process/turn/request/tool 是其 child；不能把这说成每轮独立 root。异步 turn 失败由 session.error 最终边界记录 ERROR，同会话通过 TraceId 检索，具体轮次仍须 SpanId/实体与事件定位。
- `operation(&trace, operation, layer)` 是子操作；不在每个纯函数建 span，不用同一用户动作的多个互不相关 root 冒充跨层调用链。
- 当前 UI 后台协调入口 `state::run` 创建 `ui.background`，源码位置标识具体消费者；工作和回调必须处在同一 span。业务上的独立异步 turn/request 有自己明确生命周期，关联稳定实体 ID。
- 每个操作恰有一种终态：成功 `finish`、失败 `fail(code)`、取消 `cancel(reason)`、超时 `timeout(limit_ms)`。`UNFINISHED` 只表示 guard 被意外丢弃，不可作为正常控制流。
- panic 期间 hook 在栈展开前同步写一条 ERROR；随后 guard 的 WARN/UNFINISHED 说明操作没有完成，不是第二次 ERROR。禁止捕获 panic 并转成普通协议错误后继续操作不完整状态。
- `thread::spawn`、后台 executor、异步任务、channel envelope 必须捕获并在消费者进入已有 span。异步 future 不可跨 await 持有 entered guard；在实际执行片段进入，或使用 tracing instrumentation。
- view/window 已关闭、generation/身份变化使结果失效时，显式记录 DEBUG 丢弃原因，不能谎报“UI 已应用成功”；不得让旧回调修改新对象。
- UI 与实体读写：不要在 `Entity::update` 内再次 read/update 同一实体；需要窗口/弹层时传捕获的身份或延迟到当前更新结束。不要为掩盖重入 panic 使用 `catch_unwind`。
- Gateway 的 token 注册 span 只代表 session/setup 上下文，不能冒充当前 turn。现有引擎 HTTP 协议不带可信 per-turn trace identity，因此网关请求目前只能准确关联注册上下文与内部 provider/key ID；不得从日志宣称该路径已贯通当前 turn。未认证/任意非法路径不逐条 WARN，防止日志放大；认证后的配置/网络/上游失败必须保留安全 WARN 事实，响应头 DEBUG 不等同流完成。需要精确 turn 关联时必须先定义可信协议，不可猜测。

## 3. 事件与字段

- 事件名保持稳定的 `module.object.action`，优先小写点分；宏中的消息是事件名，不用用户文案、完整路径、模型输出拼接。
- 格式由 `GrepFormat + SpanFields` 唯一维护：`TraceId/SpanId/ParentSpanId/Layer/ME/SourceFile/SourceLine/EV/RT/Result/Error/Reason/Limit`。业务字段不得冒充 EV 等保留字段。
- 字段用稳定错误码、内部 ID、协议枚举、HTTP status、计数、大小和耗时。不以错误中文文案或字符串包含判断错误类别。
- 跨库错误保留 typed source 供代码处理；写日志只取稳定分类和必要安全摘要。`error!(%error)`、`?error`、`format!("{error:#}")` 必须逐项证明不携带 SQL/路径/上游内容，不能默认安全。
- 不需要每行重复 TraceId 字段；进入正确 span，让 formatter 继承。没有操作上下文的启动/panic 不虚构父链。
- 相同循环失败汇总计数，必要时记录首个稳定错误码；不逐模型、逐文件、逐 token 打日志。协议 send/receive 类型和长度是 DEBUG，不是 INFO。

## 4. 数据安全

所有级别都禁止记录：API key、Bearer/Authorization/Cookie、密码、环境变量值、凭据 URL、用户提示词/回答、工具参数/结果、文件内容、原始 HTTP body、数据库 SQL/绑定值、完整 stderr、用户绝对路径。

- 不依赖“这段字符串一般不含敏感信息”。外部错误文本默认不可信。
- 用内部 ID、计数、typed code、OS error kind/code 替代路径和错误原文；编译期源码定位保留仓库相对路径，移除开发机目录。
- panic payload 不原样记录，也不根据正文关键词选择业务恢复；只输出载荷类型、关联哈希、位置和栈。哈希仅用于关联，不作为匿名化用户正文的许可。
- UI 可读错误必须中文、简明；诊断 ID 可复制。原始参数/响应不能作为“诊断能力”泄露，技术细节默认折叠。

## 5. Result 与资源所有权

- 服务层返回 `core::Error`，UI/组合根负责最终处理；不在业务库安装 subscriber 或 panic hook。
- 正常业务动作不得 `let _ = result`、`.ok()` 丢失败。可选探测仅允许明确 NotFound/Unavailable，其他错误必须传播或说明降级并 WARN。
- Drop、退出、资源清理可以尽力而为，但失败需 DEBUG 或 WARN 的稳定摘要；不能写“已删除/已终止”而实际失败。不重试副作用未知的写操作。
- 后台线程/channel 关闭要分清预期取消与真实失败；不可把 worker panic 或发送失败包装成空成功。
- `OperationGuard` 所有者与资源所有者保持唯一；不要另建 logging trait、通用拦截器、重试框架或第二套状态机。

## 6. Panic 与落盘

`thinkrail_observability::init` 成功后安装进程级 Rust panic hook：记录 `code:RUST_PANIC`、源文件/行列、线程 ID、payload 分类/哈希与强制捕获的 backtrace。当前 span 自动提供 TraceId/ME。panic 专用 ERROR 不受 `THINKRAIL_LOG=off` 关闭，直接写同一滚动文件，不依赖异步 WorkerGuard 的 Drop。

普通事件仍走非阻塞队列，避免 UI 日常磁盘阻塞。生产 panic hook 不调用会原样打印 payload 的默认 stderr hook，不改变 Rust unwind/abort 语义。日志 I/O 本身失败不能递归触发日志或业务重试。

边界：Rust hook 不覆盖 `TerminateProcess`、断电、访问违规、栈溢出、分配器直接 abort。此类问题须查 Windows Application/WER；缺少 PDB 时调用栈可能只有地址，不能声称获得符号化栈。保留与发布 EXE 同版本的构建产物用于离线符号化，绝不将用户数据库和内存转储放进普通安装包。

## 7. AI 开发与审查清单

新增功能前：

1. 阅读本文、`AI工程规范.md`、相关模块设计与现有同类消费者。
2. 列出入口 → service → store/external → UI completion，明确 span/线程/资源所有者。
3. 列出成功、验证失败、上游失败、持久化失败、取消、超时、窗口关闭和 stale completion 的结果与日志责任。
4. 搜索所有调用方；公开 API 用 LSP 引用，服务器不可用时说明并按源码核对。

交付前必须：

- 定向行为回归覆盖真实错误/状态，不测试“宏被调用/源码包含字符串”。
- 读取真实 writer 输出，验证 INFO 下有入口/终态；DEBUG 增加层级而不泄漏正文；同一 TraceId 不串线、一次失败只一条最终 ERROR。
- 对清理、channel、thread、`let _`/`.ok()` 和 `unwrap_or_default` 逐项判断，不机械替换所有 Option 默认。
- panic 用隔离子进程验证：日志级别关闭仍 ERROR、abort 前已落盘、敏感载荷不存在、调用链正确；不在用户正式进程制造崩溃。
- GUI 修复运行实际程序，用临时 data-dir、假密钥和本地回环，验证成功/失败/取消；不发送真实供应商凭据。
- 运行 fmt、严格 clippy 和 workspace tests；记录命令、结果、ignored 与未验证范围。
- 更新唯一规范和受影响设计，不保留互相矛盾的旧示例。没有观察到的真实链路不可写“全通过”。
