# 02 规划分析

事实见 [调研](01-research.md)，接口见 [详细设计](04-detail.md)，任务见 [开发任务](05-development.md)。

## 1. 范围

### 必须交付

- Windows GPUI 原生桌面应用，不使用 WebView。界面对标原版 ThinkRail（U04）。
- pi、OMP、DSH 三个真实后端，各自按官方协议接入。设置里管理档案、选择默认档案；聊天绑定创建时的档案版本，不随默认档案变化。
- 项目、worktree、Git 状态与 diff、只读文件阅读、终端、TODO / 计划、评论审查。
- 宿主 TODO / 审查工具可由 Agent 调用（U08）。

### 不做

- 不在原 ThinkRail 仓库改造，不修改其 Web / CLI（U01）。
- 不导入 `~/.thinkrail` 的旧数据（U07）。
- 应用安装包不带引擎及其运行时；用户没装时由“编码搭档”页按需下载固定版本（U06，agent-settings 04 §7.10）。
- 不重写任何引擎的模型循环、工具调度、压缩或计费。
- 不做跨引擎上下文迁移、自动切换后端，也不在崩溃后自动重发 prompt。
- 不做可编辑代码编辑器。文件阅读保持只读，与原版一致。

### 后续阶段（本期不做，不做空壳）

PR 创建与查看、Specs 图、十一类资源专用预览（图片 / SVG / CSV / JSON / notebook / PDF / HTML 等）、安装包与自动更新、多语言。这些在 05 中单独列为未完成项，不放占位界面。

## 2. 决策记录

| 决策 | 选择 | 理由与代价 |
|---|---|---|
| A01 | 纯 Rust 业务服务，进程内调用 | 用户决定（U02）。少一个后台进程和一套协议；代价是原版 TS 业务逻辑要用 Rust 重写 |
| A02 | 引擎走官方进程协议：pi `--mode rpc`，OMP `--mode rpc-ui`，DSH ACP | 不嵌入 JS SDK。代价是能力受协议限制，宿主工具要另走 MCP |
| A03 | 每个聊天一个引擎子进程 | 档案、配置目录和环境变量天然隔离。代价是进程数更多；pi / OMP 不共享 worker |
| A04 | 契约放在 Rust `core` crate（类型 + trait），不另设 schema 生成 | 只有 Rust 一个消费者；JSON 只出现在引擎协议和持久化文件里 |
| A05 | backend 表示实现种类，profile 表示配置档案，默认值选的是 profile | 同一引擎可以有多套配置（例如工作 / 个人） |
| A06 | 宿主全局 `ChatId` 与引擎 `NativeSessionKey` 分开 | 不同引擎的会话 id 可能冲突；恢复时只用 native key |
| A07 | `Capabilities` 按后端如实声明 | UI 只提供真实可用的功能 |
| A08 | 引擎拥有执行历史；宿主拥有绑定、业务数据和界面投影 | 不复制引擎会话状态；DSH 不能回放历史，必须如实提示 |
| A09 | 宿主 TODO / 审查工具通过宿主内置的 MCP server 提供 | 三个引擎走同一条路径；具体接法见 04 §6 |
| A10 | PTY 由 Rust portable-pty 管理，GPUI 用 vt100 解析并绘制 | 同一个 shell 只有一个所有者 |
| A11 | 不开网络监听 | 进程内调用，不存在本机端口被其他程序访问的风险 |
| A12 | 不自动切换后端，不跨崩溃重发 | 执行状态无法确定，重发可能重复修改文件或产生费用 |
| A13 | 三个 crate：core / services / app | 面向接口、可单独测试；app 只依赖 trait（U05） |
| A14 | 视觉数据逐值取自原版主题和令牌，生成 Rust 常量 | 对标原版，不另造一套色板（U04） |

## 3. 技术选型（全部为最新正式版并精确锁定）

| 用途 | 选型 |
|---|---|
| 工具链 | Rust 1.99.1，edition 2024 |
| UI | gpui-kit 0.8.1（启用 `gpui-fast` 特性：gpui-fast 0.1.12、gpui-component 0.8.1） |
| 终端 | portable-pty 0.9.0、vt100 0.18.1 |
| 错误 | thiserror 2.0.21（库层），anyhow 1.0.104（仅 `main`） |
| 日志 | tracing 0.1.44、tracing-subscriber 0.3.23、tracing-appender 0.2.5 |
| 序列化 | serde 1.0.229、serde_json 1.0.154 |
| 其他 | uuid 1.29.0、sha2 0.11.1、base64 0.23.1、fs2 0.4.3、parking_lot 0.13.0、async-channel 2.5.0 |

升级流程：查询 crates.io 的 `max_stable_version`，确认未撤回，再跑 workspace 构建、clippy、单元测试、真实 PTY 测试、三个引擎的握手测试和窗口冒烟测试。

## 4. 里程碑

| 阶段 | 交付 | 退出标准 |
|---|---|---|
| M1 架构 | workspace 三层、core 契约、错误与日志规范 | 编译通过；业务模块只能经 trait 调用 |
| M2 服务 | 工作区 / Git / 文件 / 档案 / 审查计划 / PTY，三个 AgentRuntime | 单测加真实 PTY 测试，pi / OMP / DSH 握手测试 |
| M3 界面 | 对标原版的外壳、项目树、聊天、终端、文件 / 变更、设置 | 真实窗口里逐项操作，并与原版截图对照 |
| M4 宿主工具 | MCP 桥加 TODO / 审查工具 | 三个引擎各自真实调用一次，或如实记录不支持的原因 |
| M5 后续 | PR、Specs、资源预览、打包 | 单独排期 |

## 5. 风险触发

- 安全项失败（自动批准、档案之间凭据串用）属于阻断问题，不能降级为界面提示。
- 引擎缺少必要接口时，先按固定版本源码复现，再调整接入方式；不调用私有接口，也不用 mock 冒充。
- GPUI 组件不够用时，补充实现或做组件适配，不改用 WebView。
